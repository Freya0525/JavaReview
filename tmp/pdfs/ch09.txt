1.1 什么是⽣活的异常
男主⻆⼩明每天开⻋上班，正常⻋程1⼩时。但是，不出意外的话，可能会出现意外。
出现意外，即为异常情况。我们会做相应的处理。如果不处理，到不了公司。处理完了，就可以正常开⻋去公司。
1.2 什么是程序的异常
在使⽤计算机语⾔进⾏项⽬开发的过程中，即使程序员把代码写得尽善尽美，在系统的运⾏过程中仍然会遇到⼀些
问题，因为很多问题不是靠代码能够避免的，⽐如：客户输⼊数据的格式问题，读取⽂件是否存在，⽹络是否始终保
持通畅等等。
异常 ：指的是程序在执⾏过程中，出现的⾮正常情况，如果不处理最终会导致JVM的⾮正常停⽌。
异常指的并不是语法错误和逻辑错误。语法错了，编译不通过，不会产⽣字节码⽂件，根本不能运⾏。
代码逻辑错误，只是没有得到想要的结果，例如：求a与b的和，你写成了a-b
1.3 异常的抛出机制
Java中是如何表示不同的异常情况，⼜是如何让程序员得知，并处理异常的呢？
Java中把不同的异常⽤不同的类表示，⼀旦发⽣某种异常，就创建该异常类型的对象，并且抛出（throw）。然后程
序员可以捕获(catch)到这个异常对象，并处理；如果没有捕获(catch)这个异常对象，那么这个异常对象将会导致程
序终⽌。

2.1 Throwable
java.lang.Throwable 类是Java程序执⾏过程中发⽣的异常事件对应的类的根⽗类。
Throwable中的常⽤⽅法：
public void printStackTrace()：打印异常的详细信息。

public String getMessage()：获取发⽣异常的原因。
2.2 Error 和 Exception
Throwable可分为两类：Error和Exception。分别对应着java.lang.Error与java.lang.Exception两个类。
Error：Java虚拟机⽆法解决的严重问题。如：JVM系统内部错误、资源耗尽等严重情况。⼀般不编写针对性的代码
进⾏处理。
例如：StackOverflowError（栈内存溢出）和OutOfMemoryError（堆内存溢出，简称OOM）。
Exception: 其它因编程错误或偶然的外在因素导致的⼀般性问题，需要使⽤针对性的代码进⾏处理，使程序继续
运⾏。否则⼀旦发⽣异常，程序也会挂掉。例如：
空指针访问
试图读取不存在的⽂件
⽹络连接中断
数组⻆标越界
说明：
1. ⽆论是Error还是Exception，还有很多⼦类，异常的类型⾮常丰富。当代码运⾏出现异常时，特别是
我们不熟悉的异常时，不要紧张，把异常的简单类名，拷⻉到API中去查去认识它即可。
2. 我们本章讲的异常处理，其实针对的就是Exception。

2.3 编译时异常和运⾏时异常
Java程序的执⾏分为编译时过程和运⾏时过程。有的错误只有在运⾏时才会发⽣。⽐如：除数为0，数组下标越界
等。
因此，根据异常可能出现的阶段，可以将异常分为：
编译时期异常（即checked异常、受检异常）：在代码编译阶段，编译器就能明确警示当前代码可能发⽣
（不是⼀定发⽣）xx异常，并明确督促程序员提前编写处理它的代码。如果程序员没有编写对应的异常处理
代码，则编译器就会直接判定编译失败，从⽽不能⽣成字节码⽂件。通常，这类异常的发⽣不是由程序员的
代码引起的，或者不是靠加简单判断就可以避免的，例如：FileNotFoundException（⽂件找不到异常）。
运⾏时期异常（即runtime异常、unchecked异常、⾮受检异常）：在代码编译阶段，编译器完全不做任何
检查，⽆论该异常是否会发⽣，编译器都不给出任何提示。只有等代码运⾏起来并确实发⽣了xx异常，它才
能被发现。通常，这类异常是由程序员的代码编写不当引起的，只要稍加判断，或者细⼼检查就可以避免。
java.lang.RuntimeException类及它的⼦类都是运⾏时异常。⽐如：
ArrayIndexOutOfBoundsException数组下标越界异常，ClassCastException类型转换异常。

4. 异常的处理
4.1 异常处理概述
在编写程序时，经常要在可能出现错误的地⽅加上检测的代码，如进⾏x/y运算时，要检测分⺟为0，数据为空，输
⼊的不是数据⽽是字符等。过多的if-else分⽀会导致程序的代码加⻓、臃肿，可读性差，程序员需要花很⼤的精⼒
“堵漏洞”。因此采⽤异常处理机制。
Java异常处理
Java采⽤的异常处理机制，是将异常处理的程序代码集中在⼀起，与正常的程序代码分开，使得程序简洁、优雅，并
易于维护。
Java异常处理的⽅式：
⽅式⼀：try-catch-finally
⽅式⼆：throws + 异常类型

===== PAGE 10 =====
4.2 ⽅式1：捕获异常（try-catch-finally）
Java提供了异常处理的抓抛模型。
前⾯提到，Java程序的执⾏过程中如出现异常，会⽣成⼀个异常类对象，该异常对象将被提交给Java运⾏时
系统，这个过程称为抛出(throw)异常。
如果⼀个⽅法内抛出异常，该异常对象会被抛给调⽤者⽅法中处理。如果异常没有在调⽤者⽅法中处理，它
继续被抛给这个调⽤⽅法的上层⽅法。这个过程将⼀直继续下去，直到异常被处理。这⼀过程称为捕获
(catch)异常。
如果⼀个异常回到main()⽅法，并且main()也不处理，则程序运⾏终⽌。
4.2.1 try-catch-finally基本格式
捕获异常语法如下：

===== PAGE 11 =====
try{
...... //可能产⽣异常的代码
}
catch( 异常类型1 e ){
...... //当产⽣异常类型1型异常时的处置措施
}
catch( 异常类型2 e ){
...... //当产⽣异常类型2型异常时的处置措施
}
finally{
...... //⽆论是否发⽣异常，都⽆条件执⾏的语句
}
1、整体执⾏过程：
当某段代码可能发⽣异常，不管这个异常是编译时异常（受检异常）还是运⾏时异常（⾮受检异常），我们都可以
使⽤try块将它括起来，并在try块下⾯编写catch分⽀尝试捕获对应的异常对象。
如果在程序运⾏时，try块中的代码没有发⽣异常，那么catch所有的分⽀都不执⾏。
如果在程序运⾏时，try块中的代码发⽣了异常，根据异常对象的类型，将从上到下选择第⼀个匹配的catch
分⽀执⾏。此时try中发⽣异常的语句下⾯的代码将不执⾏，⽽整个try...catch之后的代码可以继续运⾏。
如果在程序运⾏时，try块中的代码发⽣了异常，但是所有catch分⽀都⽆法匹配（捕获）这个异常，那么
JVM将会终⽌当前⽅法的执⾏，并把异常对象“抛”给调⽤者。如果调⽤者不处理，程序就挂了。
2、try
捕获异常的第⼀步是⽤try{…}语句块选定捕获异常的范围，将可能出现异常的业务逻辑代码放在try语句块
中。

===== PAGE 12 =====
3、catch (Exceptiontype e)
catch分⽀，分为两个部分，catch()中编写异常类型和异常参数名，{}中编写如果发⽣了这个异常，要做什
么处理的代码。
如果明确知道产⽣的是何种异常，可以⽤该异常类作为catch的参数；也可以⽤其⽗类作为catch的参数。
⽐如：可以⽤ArithmeticException类作为参数的地⽅，就可以⽤RuntimeException类作为参数，或者⽤所
有异常的⽗类Exception类作为参数。但不能是与ArithmeticException类⽆关的异常，如
NullPointerException（catch中的语句将不会执⾏）。
每个try语句块可以伴随⼀个或多个catch语句，⽤于处理可能产⽣的不同类型的异常对象。
如果有多个catch分⽀，并且多个异常类型有⽗⼦类关系，必须保证⼩的⼦异常类型在上，⼤的⽗异常类型
在下。否则，报错。
catch中常⽤异常处理的⽅式
public String getMessage()：获取异常的描述信息，返回字符串
public void printStackTrace()：打印异常的跟踪栈信息并输出到控制台。包含了异常的类型、
异常的原因、还包括异常出现的位置，在开发和调试阶段，都得使⽤printStackTrace()。

4.2.5 异常处理的体会
前⾯使⽤的异常都是RuntimeException类或是它的⼦类，这些类的异常的特点是：即使没有使⽤try和
catch捕获，Java⾃⼰也能捕获，并且编译通过 ( 但运⾏时会发⽣异常使得程序运⾏终⽌ )。所以，对于这类
异常，可以不作处理，因为这类异常很普遍，若全处理可能会对程序的可读性和运⾏效率产⽣影响。
如果抛出的异常是IOException等类型的⾮运⾏时异常，则必须捕获，否则编译错误。也就是说，我们必须
处理编译时异常，将异常进⾏捕捉，转化为运⾏时异常。
4.3 ⽅式2：声明抛出异常类型（throws）
如果在编写⽅法体的代码时，某句代码可能发⽣某个编译时异常，不处理编译不通过，但是在当前⽅法体中
可能不适合处理或⽆法给出合理的处理⽅式，则此⽅法应显示地声明抛出异常，表明该⽅法将不对这些异常
进⾏处理，⽽由该⽅法的调⽤者负责处理。

===== PAGE 18 =====
具体⽅式：在⽅法声明中⽤throws语句可以声明抛出异常的列表，throws后⾯的异常类型可以是⽅法中产
⽣的异常类型，也可以是它的⽗类。

4.4 两种异常处理⽅式的选择
前提：对于异常，使⽤相应的处理⽅式。此时的异常，主要指的是编译时异常。
如果程序代码中，涉及到资源的调⽤（流、数据库连接、⽹络连接等），则必须考虑使⽤try-catch-finally来

开发中，⽅法a中依次调⽤了⽅法b,c,d等⽅法，⽅法b,c,d之间是递进关系。此时，如果⽅法b,c,d中有异常，
我们通常选择使⽤throws，⽽⽅法a中通常选择使⽤try-catch-finally。

6. ⾃定义异常
6.1 为什么需要⾃定义异常类
Java中不同的异常类，分别表示着某⼀种具体的异常情况。那么在开发中总是有些异常情况是核⼼类库中没有定义
好的，此时我们需要根据⾃⼰业务的异常情况来定义异常类。例如年龄负数问题，考试成绩负数问题，某员⼯已在
团队中等。
6.2 如何⾃定义异常类
（1）要继承⼀个异常类型
⾃定义⼀个编译时异常类型：⾃定义类继承java.lang.Exception。
⾃定义⼀个运⾏时异常类型：⾃定义类继承java.lang.RuntimeException。
（2）建议⼤家提供⾄少两个构造器，⼀个是⽆参构造，⼀个是(String message)构造器。
（3）⾃定义异常需要提供serialVersionUID
6.3 注意点
1. ⾃定义的异常只能通过throw抛出。
2. ⾃定义异常最重要的是异常类的名字和message属性。当异常出现时，可以根据名字判断异常类型。⽐如：
TeamException("成员已满，⽆法添加");、 TeamException("该员⼯已是某团队成员");
3. ⾃定义异常对象只能⼿动抛出。抛出后由try..catch处理，也可以甩锅throws给调⽤者处理。
